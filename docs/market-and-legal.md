# 시장·경쟁·법률 검토 (초안)

> 작성일: 2026-10-23 · 법률 자문이 아닌 기획 단계 검토. 출시 전 전자금융·개인정보 전문 변호사 검토 필수.

## 0. 확정된 방향

- **보내는 사람(구매자):** 아무 은행앱/토스/카카오페이 등 *어떤 수단으로든* 이체. 별도 앱 설치·가입 불필요.
- **받는 사람(판매자):** 서비스에 등록한 **지정 입금계좌**로만 받음. 이 계좌의 입금만 "확정"의 근거가 됨.

### "지정계좌"를 누구 명의로 둘 것인가 — 가장 중요한 결정

| 구조 | 설명 | 규제 부담 | 판단 |
|---|---|---|---|
| ① **판매자 본인 명의 계좌** 지정 | 판매자 계좌로 바로 입금. 우리는 입금 사실만 확인 | 낮음 (자금 보관·정산 안 함) | **초기 추천** |
| ② 제휴은행의 **판매자 명의 전용계좌** | 제휴은행에서 판매자 명의로 계좌 개설, 은행이 실시간 입금통지 제공 | 낮음~중 (은행이 계좌 운영) | 2단계 목표. 확인 신뢰도 최상 |
| ③ **서비스(회사) 명의 계좌/가상계좌**로 받아 판매자에게 정산 | 돈이 우리를 거쳐감 | 높음 — 전자지급결제대행업(PG) 등록, 자본금 요건, 정산자금 관리 의무 | 초기 비추천 |

①·②는 "돈은 한 번도 우리 손을 거치지 않는다"는 점이 규제 측면에서도, 상인 신뢰 측면에서도 가장 큰 무기다.

## 1. 시장 현실

| 지표 | 수치 | 시사점 |
|---|---|---|
| 결제 건수 기준 계좌이체 비중 (한국은행, 2024 조사) | **3.7%** (현금 15.9%, 신용카드 46.2%) | 전체 결제로 보면 계좌이체는 작은 시장 |
| 전통시장·노점·플리마켓·개인거래의 이체 비중 | 공식 통계 없음 | 체감상 훨씬 높음 → **직접 조사로 검증 필요** |
| 현금 감소 추세 | 2013년 41.3% → 2024년 15.9% | 현금 → 이체로 넘어가는 영역이 우리 타깃 |

**결론:** "모든 결제"가 아니라 **카드단말기가 없거나 쓰기 싫은 곳**(노점, 푸드트럭, 플리마켓, 농산물 직거래, 개인 레슨·서비스, 중고 직거래, SNS 마켓)이 진짜 시장.

## 2. 경쟁 서비스와 실제 이용 현황

| 서비스 | 방식 | 실제 이용 | 우리가 배울 점 |
|---|---|---|---|
| **제로페이** | 상인 QR → 손님이 앱으로 계좌 간 결제, 소상공인 수수료 0% | 가맹점은 150만+ 이지만 2022년 기준 **60% 이상이 결제실적 0원**, 결제액 대부분이 지역상품권 | 상인 가입 ≠ 사용. **손님에게 새 앱/새 습관을 요구하면 실패** |
| **카카오페이·토스·네이버페이 QR** | 손님이 해당 앱으로 QR 스캔 결제 | 대형사 위주 성장, 오프라인은 카드단말기(토스 프론트 등) 중심 | 강력하지만 손님이 그 앱 사용자여야 함 |
| **입금알리미 띵동** | 판매자 폰의 은행 알림을 읽어 음성 안내 + 매출 집계 | Play 스토어 다운로드 1천+ (검색 결과 기준) | 기능은 있지만 확산은 미미 |
| **입금알리미 징검** (샵온에어) | 은행 알림 → AI 음성 안내, 송금 QR, "계좌이체 먹튀 방지" | 정확한 수치 미확인 (제3자 통계 약 1.6만, 지표 불명확) | **우리 아이디어와 가장 가까운 경쟁자.** 판매자 쪽 확인만 하고, 구매자가 받는 확정 영수증은 확인되지 않음 |
| **RTPay / 페이액션** | 온라인 쇼핑몰 무통장입금 ↔ 주문 자동 매칭 (은행 알림 기반) | 페이액션 자체 주장 1,000+ 기업. 유료(RTPay 3개월 29,700원, 페이액션 월 9,900~33,000원) | 오프라인이 아닌 **온라인 쇼핑몰** 시장. 돈 내고 쓰는 수요가 확인된 영역 |
| **은행 앱 입금 푸시** | 판매자 본인만 확인 | 누구나 사용 | 무료·기본 기능. 이것보다 확실히 나아야 함 |
| 카드 단말기 | 카드 결제 | 가장 일반적 | 수수료·단말기 비용·정산 지연이 상인의 불만 |

## 3. 이 서비스만으로 경쟁력이 있나? — 솔직한 평가

**"입금 확인" 기능 하나만으로는 부족하다.**
- 기능 자체는 알림 앱들이 이미 하고 있고, 토스·카카오가 마음먹으면 빠르게 만들 수 있다.
- 판매자 혼자 확인하는 것은 은행 푸시로도 이미 된다.

**경쟁력이 생기는 지점 (조합이 해자)**
1. **양쪽 동시 확정** — 판매자뿐 아니라 *구매자도* 서버가 검증한 확정 영수증을 받는다. 기존 알림 앱은 판매자 혼자 보는 구조. 분쟁 방지라는 원래 목적을 정확히 해결하는 건 이 부분.
2. **주문 매칭** — "누가, 무엇에 대해" 보낸 돈인지 연결. 같은 금액이 동시에 와도 구분.
3. **손님은 아무것도 설치 안 함** — 제로페이의 실패 원인을 피하는 설계.
4. **상인에게 쌓이는 장부·세무·금융 데이터** — 쓰면 쓸수록 떠나기 어려워지는 구조(전환 비용).
5. **현장 밀착 영업** — 상인회·지자체·플리마켓 주최측 단위 도입. 대형사가 가장 약한 영역.

**반드시 검증할 위험**
- ⚠️ **"기록이 남는 것"을 싫어하는 상인**: 일부 상인은 매출 노출(세금)을 우려해 기록 서비스를 꺼릴 수 있다. 반대로 기록이 필요한 상인(대출·정책자금이 필요한 사람, 분쟁이 잦은 사람, 사업 규모를 키우려는 사람)이 1차 타깃.
- 손님이 주문코드를 실제로 입력해 주는가 (딥링크 지원 범위).
- 시장 규모: 계좌이체 비중이 작다는 공식 통계와 현장 체감의 차이.

## 4. 법에 걸리지 않게 시작하는 단계별 경로

### 원칙
- **돈을 받지도, 맡지도, 정산하지도 않는다** (초기).
- "결제 보증", "입금 보장" 같은 표현을 쓰지 않는다 → **"입금 확인 기록"** 으로 표현 (보증·보험성 오해 방지).
- 은행 아이디/비밀번호를 받아 대신 로그인하는 **스크래핑 방식은 쓰지 않는다**.

### 단계별

| 단계 | 구조 | 필요한 것 | 비고 |
|---|---|---|---|
| **0. 검증 (지금)** | 판매자 본인 계좌 + 판매자 안드로이드 폰의 은행 입금 알림을 *기기 안에서* 읽어 확인 | 사업자등록, 개인정보처리방침·동의(구매자 이름·금액은 개인정보), 최소수집·보관기간 설정 | 자금 이동 관여 없음 → 전자금융업 등록 대상 아닐 가능성 높음 (법률 확인) |
| **1. 정식화** | 오픈뱅킹 조회 API 또는 **은행 제휴 입금통지** | 금융결제원 오픈뱅킹 이용기관 승인(이용신청 → 개발·보안점검 → 계약) 또는 은행과 제휴 계약 | 보안점검 등에 수개월 소요. iOS 판매자도 지원 가능 |
| **2. 확장 (선택)** | 거래별 가상계좌·에스크로(온라인 개인거래용) | **직접 하려면 PG 등록**(분기 결제대행 규모별 자본금 요건, 소규모 구간도 수억 원) / **아니면 기존 PG와 제휴** | 제휴 구조라도 우리가 정산을 "대행·매개"하면 등록 대상이 될 수 있어 구조 설계 시 법률 확인 |
| 금융상품 | 대출 연결 | 온라인 대출중개 관련 등록(금융소비자보호법) 또는 금융사 제휴 광고 형태 | 직접 대출 X |
| 현금영수증 | 이체 건 현금영수증 발급 | 국세청 현금영수증 사업자 승인 또는 승인 사업자와 제휴 | |
| 규제가 애매할 때 | 금융규제 샌드박스(혁신금융서비스) 신청 | 금융위원회 | 한시적 특례로 시작 가능 |

### 지금 당장 할 일
1. 상인 20~30명 인터뷰: 이체 분쟁 경험 빈도, 기록에 대한 태도, 카드 대비 이체 비중.
2. 변호사 1회 자문: 단계 0 구조가 전자금융업 등록 없이 가능한지, 개인정보 동의 문구.
3. 단계 0 MVP 제작 → 시장 1곳에서 4주 운영.
